# oneCR v0.2.0 — Privilege bridge & call detection

**Milestone 2.** oneCR can now see calls — cellular and VoIP — prove the shell
privilege bridge that real recording will ride on, and log everything locally.
This is a **detection-only** build: no audio is recorded yet (that's M3, v0.3.x).

## Highlights

- **Shizuku privilege bridge.** oneCR binds a tiny, auditable AIDL shell service
  (`exec` + `getUid`, ~40 lines) inside Shizuku and runs as the shell user
  (UID 2000). A "Verify bridge" button runs `id` and shows `uid=2000(shell)`
  when everything is wired. Health is monitored continuously (ping + binder
  death + reboot detection) with one-tap repair actions when it drops.
- **Cellular call detection.** Incoming / outgoing / missed call events with
  direction, duration and caller ID (number + cached contact name, resolved
  locally from the newest call-log row after each call).
- **VoIP call detection.** Ongoing WhatsApp / Telegram / Signal / Meet / Zoom /
  Discord calls are recognized from a debounced rule: ongoing call notification
  **and** active voice-communication audio. Only the notification category flag
  is read — never the content.
- **Setup wizard + Permission center + Event log.** A first-launch wizard walks
  through Shizuku setup with per-OEM battery/autostart steps (OPPO/OnePlus/
  Realme, Xiaomi, Samsung, vivo auto-detected); Settings gets a live permission
  center and a local event log (`files/logs/events.jsonl`).
- **Detection foreground service.** Detection survives the app being closed;
  the notification shows the live call state.
- **22 unit tests** covering the call state machine, the VoIP heuristic and the
  event store — all green.

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Capture (from M3) will require
  Android 11+, checked at runtime.
- **Updating from the v0.1.2 pre-release:** this build is signed with a **new
  release keystore** (the original was lost with the build machine), so Android
  will refuse an in-place update once. **Uninstall v0.1.2 first, then install
  v0.2.0.** From v0.2.0 onward the shipped keystore stays stable — future
  releases update in place. (Building yourself? Drop your old `.signing/` folder
  from the v0.1.2 source zip into the v0.2.0 source before running `build.bat`
  and even that one uninstall disappears.)
- Grant the permissions the wizard asks for. Detection degrades gracefully —
  the Dashboard card tells you exactly which part is off.
- For VoIP detection, enable notification access for oneCR when the wizard
  offers it (you can also do it later from the Permission center).

## Known issues

- Numbers on some OEMs only arrive via call-log enrichment a moment after the
  call ends (the log shows the raw event first).
- VoIP apps that don't post `CATEGORY_CALL` ongoing notifications (or whose
  notifications are suppressed) won't be detected until the M3 manual-record
  button.
- Shizuku dies on reboot by design — oneCR notices and shows a repair banner;
  start Shizuku again and the bridge reconnects within ~30 s or instantly via
  "Re-check bridge".
- The embedded-ADB bridge (no Shizuku needed at all) lands in v0.3.0.
