# oneCR v0.3.3 — the capture engine starts + the app updates itself

**v0.3.3** (versionCode 12) ships two headline features and one important CI fix.

## 1. Capture engine — M3 step 1

Recording is real. The Dashboard's **Record now** button and the Settings
**auto-record switch** (off by default) drive the new recording pipeline:

- **Probe-verified source fallback** — before recording, oneCR verifies the
  candidate audio sources actually produce sound (many OEMs accept VOICE_CALL
  but feed it silence on Android 11+) and walks the chain: VOICE_CALL →
  microphone. If nothing works, you get a clear event-log entry, not empty
  files.
- **Streaming WAV writer** — canonical RIFF headers, sizes patched on stop;
  a crash-recovery journal and an orphan sweep keep (and repair) recordings
  when the process dies mid-call.
- **Microphone-typed foreground service** with a Stop action and an honest
  privacy chip; it stops itself when the session ends.
- **Capture probe in Settings** (Settings → Capture (M3) → Run capture probe)
  tells you exactly which sources work on your phone.

*Known limit:* this step records through the app's own audio path — most
Android 11+ devices silence VOICE_CALL for normal apps, so recordings use the
microphone fallback (near end; far end via speakerphone). The shell capture
dex — the privileged telephony mix every device grants — is the next M3 step.

## 2. Update checker — oneCR updates itself

The app now checks GitHub Releases (one public URL, throttled to once per
hour, nothing identifying in the request):

- **Notification**: "oneCR v0.3.3 available" — tap it to open the update page;
  expand it for the release notes with **Update** and **Cancel** buttons.
- **Update page above everything** when a new version is found on open: big
  version banner, release notes, size, "View on GitHub", with **Cancel** and
  **Update** buttons.
- **Update flow**: Android's per-app **"Install unknown apps"** grant is
  requested first → the APK downloads from GitHub with a live progress bar →
  **SHA-256 is verified against the release's SHA256SUMS.txt** → the system
  installer opens automatically.
- Cancel snoozes reminders for that version for 24 hours; a *newer* release
  overrides the snooze. About → **Check for updates** runs a check on demand.

## 3. Fixed

- **The release workflow can publish again**: tag pushes never triggered the
  build job (branches-only trigger), so the tag-gated release job was skipped
  forever. Tags now start CI; tagging `0.3.3` publishes the APK + checksums.
- Restored two embedded-ADB protocol files (`PairingCipher`, `PairingStore`)
  and the HKDF test vectors that had been lost from the source tree; the full
  TLS 1.3 + SPAKE2 + AES-128-GCM pairing mock re-verifies the protocol.

## Install

- Android 8.0+ to install; the embedded-ADB bridge needs Android 11+.
- **Update from v0.3.0/v0.3.1 in place** (stable keystore since v0.3.0). Every
  future release can update itself through the new checker.
- From v0.2.x or earlier: uninstall first (the keystore was rotated at v0.3.0).
- Verify: `sha256sum oneCR-v0.3.3.apk` against `SHA256SUMS.txt` (the in-app
  updater does this for you).

Privacy: the update check fetches one public API URL and the download fetches
the release asset — oneCR still has no accounts, no telemetry, and your call
audio never leaves the phone. See PRIVACY.md.
