# oneCR v0.2.2 — Top bar + notification center, one-by-one permissions

**UX release.** oneCR now has a proper shell: a branded top app bar on every
screen with a **notification bell in the top-right**. The bell opens the new
**notification center** — one place that shows anything the app needs, every
error, and the activity log, with an unread badge. Permissions are no longer
asked as a bundle: **every tap asks for exactly one thing.** The UI is polished
with section headers, a live Start/Stop state and consistent theming. Still
detection-only — recording arrives in M3 (v0.3.x).

## Highlights

- **Top app bar with notification center.** Every main screen has a top bar
  (logo + tab + version). The bell shows an amber badge counting
  needs + errors + unseen activity and opens the Notifications page:
  - **Needs attention** — missing permissions with one-tap grant buttons
    (each fires exactly one system dialog), "Call detection is off" with a
    start button, and privilege-bridge repair actions.
  - **Errors** — new error stream; the service now logs failures
    (foreground-service start failures, engine errors) instead of dying
    silently.
  - **Recent activity** — the detection event log as a feed (newest first).
  Opening the page marks everything read; "Mark read" resets the badge.
- **One-by-one permission wizard.** In onboarding, each permission is a card;
  the active one is highlighted and its **Allow …** button asks for that
  single permission — answer, and the next card activates
  (phone → call log → notifications on Android 13+ → notification access →
  battery). Settings → Permission center gets the same **Guided setup**:
  "Step X of Y", the rationale in front of every ask, per-item skip, exit
  anytime. Nothing is requested silently and nothing is bundled.
- **Professional UI polish.** Section headers (Live status / Activity /
  Roadmap; Appearance / Bridge / Permissions / About), a version chip on the
  Dashboard hero, Start/Stop buttons that reflect the real service state, and
  a nav/top bar pinned to the theme surface (the old baseline grey no longer
  clashes with the navy palette).
- **Under the hood:** a reactive `PermissionSnapshot` replaces the per-screen
  refresh-counter hack; 6 new unit tests pin the notification-center feed and
  badge math (31 total).

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Detection works on Android 8+;
  the embedded-ADB bridge (v0.3.0) will require Android 11+, checked at runtime.
- **Updating from v0.2.0/v0.2.1:** same release keystore — installs in place,
  nothing to do. Updating from the v0.1.2 pre-release still needs the one-time
  uninstall first (that build used the lost original key).
- **Play Protect:** if installation is blocked with "This app can request
  access to sensitive data", that is the standard caution for any sideloaded
  app with call-log permissions — not a malware verdict. Tap **More details →
  Install anyway (unsafe)**, or disable the prompts under Play Store →
  Play Protect → Settings. Full story in `docs/COMPATIBILITY.md`.

## Known issues

- Same as v0.2.1: call-log enrichment may land a moment after the call ends on
  some OEMs; VoIP apps that suppress ongoing-call notifications aren't detected
  until M3's manual record; Shizuku dies on reboot by design and oneCR shows a
  repair banner.
- The embedded-ADB bridge (no Shizuku needed at all) lands in v0.3.0.
