# oneCR v0.1.2 — installs on Android 8+ (pre-release)

**Fix release.** v0.1.1 refused to install on Android 10 and older with
"There was a problem parsing the package" — and the app icon never even showed.
That was an install-floor bug, not a corrupt file.

## What changed

- **Install floor lowered to Android 8.0 (API 26).** v0.1.1 declared
  `minSdk 30` (Android 11+), so Android's package parser rejected the whole APK
  on older devices before it could even display the icon. The capture features
  still require Android 11+, but that gate now happens at runtime, not at
  install time.
- **APK now signed with v1 + v2 + v3 signature schemes simultaneously**
  (v2 only before) for maximum compatibility across OEM package installers.
- **Local signing keystore ships in `.signing/` inside the source zip** and
  `build.bat` reuses it, so APKs you build yourself install as in-place updates
  over the prebuilt release APK — no more signature-mismatch uninstall dance
  between the two.

## What's in the box

M1 skeleton only: Compose UI shell (Dashboard / Library / Settings), adaptive
brand icon, one-command Windows build, CI, docs. Zero permissions requested,
zero features that touch your data. Detection arrives in v0.2.0.

## Install

1. Android 8.0 or newer.
2. Allow "Install unknown apps" for your browser/file manager.
3. Download with a **browser**, not a chat app — chat apps re-encode or
   truncate APK attachments and genuinely produce "problem parsing the package".
