# oneCR v0.2.4 — Dark mode that follows the app, a steadier setup wizard

**Theme and control-fix release.** The three dark-mode bugs reported on
v0.2.3 are gone: the notification panel's top bar now renders a proper
Material top app bar (white title and icons in dark mode, black in light),
the panel has a real top bar with a divider, and the **Set up oneCR wizard
finally follows the dark theme** — including when the theme is pinned to
Dark, not just when the OS is dark. The wizard's **Next / Back / Finish
buttons no longer drift**: they sit in a fixed bottom bar while the step
content scrolls. Across the app, **more icons and fewer bare words** carry
the meaning — buttons, permission tasks, theme choices and About rows all
grew leading icons. Still detection-only — recording arrives in M3 (v0.3.x).

## Highlights

- **Notification center top bar, done properly (dark-mode bug #1 and #2).**
  The hand-rolled header row drew its title with the ambient content color —
  plain black outside a Surface — so in dark mode the "Notifications" title
  and back arrow stayed black on navy. The panel is now a real Material 3
  top app bar: surface-colored bar, `onSurface` title (white in dark, black
  in light), a bell glyph next to the title, the live status line, "Mark
  read" on the right and a divider under the bar. No bottom bar, as before.
- **The setup wizard follows dark mode (dark-mode bug #3).** Previously the
  Compose palette switched, but the platform layer — the window background
  the wizard paints nothing on top of, the system bars and platform dialogs —
  kept following the OS. The app now syncs the platform night mode to the
  in-app theme setting (`AppCompatDelegate.setDefaultNightMode`, DayNight
  theme): **Dark is dark everywhere, Light is light everywhere, System
  follows the OS**, and every screen additionally paints the scheme's own
  background so nothing translucent can leak the light window underneath.
- **Fixed bottom bar in the setup wizard.** Next / Back / Finish used to
  travel with the content — on long steps they sat low, on short ones they
  jumped up. They now live in a fixed footer at the bottom edge of the
  screen: a fixed header (step icon, title, progress bar) on top, the step
  content scrolls in between, buttons never move. Back carries an arrow,
  Finish carries a check mark.
- **More icons, less prose.** The full Material icon set is now available to
  the UI (R8 strips unused icons, the release APK stays small):
  - Setup wizard: per-step header icons (rocket, phone, key, battery,
    shield, check) and distinct task icons (call log = history, notification
    access = active bell, battery = charging).
  - Dashboard: Start/Stop detection buttons carry play/stop icons.
  - Settings: theme choices have system-contrast / moon / sun icons; the
    guided permission flow and "Clear log" grew icons too.
  - About: code / privacy-tip / gavel / architecture icons, plus a chevron
    on the Project home row.
- **Build robustness fix.** `settings.gradle.kts` now lists the Aliyun
  public mirror before Maven Central. Maven Central rate-limits some IPs
  with HTTP 429, which aborted first-time builds; the mirror unblocks them
  (Central remains the canonical fallback, so CI behavior is unchanged).

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Detection works on Android 8+;
  the embedded-ADB bridge (v0.3.0) will require Android 11+, checked at runtime.
- **Updating from v0.2.0–v0.2.3:** same release keystore — installs in place,
  nothing to do. The GitHub Releases page currently hosts **v0.2.0 and
  newer**; the 0.1.x pre-releases were removed from the page, so upgrading
  from one of those means uninstalling the old build once and installing
  v0.2.4 fresh.
- **Play Protect:** if installation is blocked with "This app can request
  access to sensitive data", that is the standard caution for any sideloaded
  app with call-log permissions — not a malware verdict. Tap **More details →
  Install anyway (unsafe)**, or disable the prompts under Play Store →
  Play Protect → Settings. Full story in `docs/COMPATIBILITY.md`.

## Known issues

- Same as v0.2.3: call-log enrichment may land a moment after the call ends
  on some OEMs; VoIP apps that suppress ongoing-call notifications aren't
  detected until M3's manual record; Shizuku dies on reboot by design and
  oneCR shows a repair banner.
- Switching the theme while the app is open recreates the activity (the
  platform needs it to re-theme the window) — state is preserved, but an
  in-progress wizard step stays on the step you were on.
- The embedded-ADB bridge (no Shizuku needed at all) lands in v0.3.0.
