# oneCR v0.2.5 — Readable dark mode everywhere, a dashboard worth looking at

**Readability and polish release.** The setup wizard's black-on-navy text is
fixed — not just on the wizard, but everywhere the same latent bug hid: the
theme now provides a proper content color for the whole app, so any text
outside a card follows Dark / Light / System correctly. The **Dashboard was
redesigned**: one gradient command card (brand, live detection state and the
Start/Stop controls in a single place), a 2×2 at-a-glance stat grid, a compact
recent-activity feed and a roadmap card with a progress bar. **Settings keep
your scroll position** when you come back from the Permission center or the
Event log. The README gained a developer badge, and the logo now downloads the
latest APK. Still detection-only — recording arrives in M3 (v0.3.x).

## Highlights

- **Black text in dark mode — fixed at the root.** Compose's `LocalContentColor`
  defaults to plain black, and every `Text` that is not wrapped in a `Surface`
  (and sets no explicit color) falls back to it. In light mode that looked
  correct by accident; in dark mode the setup wizard's headline, all its bullet
  texts, the Dashboard hero title and the sub-page headlines rendered **black
  on navy**. The theme now provides `onBackground` as the app-wide content
  color — white in dark mode, ink-navy in light — so every affected screen is
  fixed at once, and any future screen inherits the correct behavior. v0.2.4
  fixed this class of bug only for the notification panel's top bar; v0.2.5
  finishes the job everywhere.
- **A modern Dashboard.** The v0.2.2 stack of same-looking status rows became
  a real hierarchy:
  - **Command card** — gradient brand header with the logo, tagline and
    version chip; the live detection state as the biggest element on the page
    (status dot, headline, call state, capability line, LIVE/OFF pill); and
    the Start/Stop + Re-check bridge controls right beneath it.
  - **At a glance** — a 2×2 grid of stat tiles: calls seen (cellular + VoIP),
    permissions granted (x/5), events logged, and the privilege bridge state.
    A warning banner with a one-tap "Fix" appears under the grid only when a
    configured bridge actually needs attention.
  - **Recent activity** — the latest events as compact rows with kind chips
    (call / voip / bridge / service / error) and relative timestamps, with a
    "View all" shortcut into the notification center.
  - **Roadmap** — a milestone card with a progress bar ("2 of 5") and the
    next-up highlight, instead of three separate placeholder cards.
- **Settings remember where you were.** The settings root's scroll state is
  now owned above the page switch, so opening the Permission center or the
  Event log and pressing back **keeps your scroll position** instead of
  snapping to the top. The position also survives tab switches and process
  death (`ScrollState.Saver`).
- **Wizard steps start at the top.** Advancing to the next setup step reset
  nothing — the old scroll offset carried over, which could land you mid-text
  on a shorter step. Each step now scrolls to its top on entry.
- **README polish.** A **developer badge** (Lalmohan Malakar) sits between the
  Platform and Version badges, and **clicking the logo downloads the latest
  release APK** — the same link the Download button uses.

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Detection works on Android 8+;
  the embedded-ADB bridge (v0.3.0) will require Android 11+, checked at runtime.
- **Updating from v0.2.0–v0.2.4:** same release keystore — installs in place,
  nothing to do. The GitHub Releases page currently hosts **v0.2.0 and
  newer**; the 0.1.x pre-releases were removed from the page, so upgrading
  from one of those means uninstalling the old build once and installing
  v0.2.5 fresh.
- **Play Protect:** if installation is blocked with "This app can request
  access to sensitive data", that is the standard caution for any sideloaded
  app with call-log permissions — not a malware verdict. Tap **More details →
  Install anyway (unsafe)**, or disable the prompts under Play Store →
  Play Protect → Settings. Full story in `docs/COMPATIBILITY.md`.

## Known issues

- Same as v0.2.4: call-log enrichment may land a moment after the call ends
  on some OEMs; VoIP apps that suppress ongoing-call notifications aren't
  detected until M3's manual record; Shizuku dies on reboot by design and
  oneCR shows a repair banner.
- Switching the theme while the app is open recreates the activity (the
  platform needs it to re-theme the window) — state is preserved, but an
  in-progress wizard step stays on the step you were on.
- The dashboard's "calls seen" tile counts within the rolling event-log
  window (newest 100 entries), not lifetime totals — lifetime statistics
  arrive with the M4 library database.
- The embedded-ADB bridge (no Shizuku needed at all) lands in v0.3.0.
