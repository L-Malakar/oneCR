# oneCR v0.3.5 — the reliability release

A CI that finally runs, a manual update check you can actually test, and a
flat minimal pass over the main screens. The app chassis is the proven
v0.3.4 one — no behavior changes beyond the list below.

## Highlights

- **The workflow is fixed — root cause removed.** Every push since v0.3.4
  failed in seconds with zero jobs, and the run was named after the file
  instead of the workflow. That is GitHub refusing to parse the file: the
  release job's step name contained an unquoted colon
  (`- name: Guard: release notes …`), which is invalid in YAML. One line
  killed every build. The workflow is rewritten clean (`oneCR CI`), kept
  100% ASCII, and validated as YAML before shipping.
- **Manual "Check for updates" on About.** The About page gains a row that
  runs a real GitHub check on demand: a spinner while checking,
  "You're on the latest version" when current, "Couldn't reach GitHub — tap
  to retry" when offline, and the full update page the moment a newer
  release exists — exactly like the automatic launch check.
- **Flat minimal design pass.** Shadowless stat tiles, unified corner
  radii (hero 20 dp, cards 16 dp, rows 14 dp), and pill chips across the
  dashboard, settings, About and event log. **The notification center and
  the setup wizard are untouched**, as requested.
- **CI is testable without a push** — the workflow has a manual
  "Run workflow" button now.

## Why the updater never found anything (and how v0.3.5 fixes it)

Both the automatic check (v0.3.4) and the new manual check call GitHub's
`releases/latest` endpoint — and that endpoint **never returns releases
marked "pre-release"**. Every release from v0.2.1 through v0.2.4 was
published as a pre-release, so the endpoint answered 404 and the updater
correctly concluded there was nothing to find.

**v0.3.5 is published as a full release** (no pre-release flag), which is
what makes `releases/latest` — and therefore both update checks — finally
work. From the next release onward, the in-app updater will actually carry
you to it.

## What works

- Cellular + VoIP call detection with caller ID (v0.2.0)
- Embedded ADB privilege bridge — no extra app (v0.3.0) — and Shizuku as the
  switchable alternative
- The 24×7 watcher surviving app close and reboots (v0.2.6)
- In-app updater: check, notify, download, launch installer (v0.3.4) plus
  the manual About-page check (v0.3.5)
- Unit tests green on CI and locally (79 tests)

## What doesn't yet

- **No audio is recorded yet.** The capture engine is the rest of M3.
- The updater installs GitHub-release APKs only; it never fetches anything
  from anywhere else.

## Install / update notes

- **Android 8.0+** (API 26); the embedded-ADB bridge needs Android 11+.
- **Updating from v0.3.x:** installs in place — same keystore, versionCode
  13. Or open **About → Check for updates** after publishing future
  releases to fetch them in-app.
- **Updating from v0.2.x or earlier:** the keystore was rotated at v0.3.0,
  so uninstall the old version once, then install v0.3.5.
- After installing, allow **"Install unknown apps"** for oneCR when the
  updater asks — that is what lets it offer the next release by itself.
