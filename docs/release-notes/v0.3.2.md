# oneCR v0.3.2 — the capture engine lands (M3 step 1)

**oneCR records cellular calls for the first time.** The privilege bridge you
already paired in v0.3.0/v0.3.1 now spawns a tiny capture process as the
adb-shell user — the process that holds `CAPTURE_AUDIO_OUTPUT` — and streams
the telephony mix into a WAV file. No root, no PC, no extra app: same
embedded-ADB pairing, now with audio on the other end of the pipe.

This release also fixes the GitHub Actions workflow that had failed on every
push since v0.3.0 (an unquoted colon in a step name was a YAML syntax error —
GitHub rejected the file at startup, runs failed with zero jobs).

**versionCode 12** — installs in place over v0.3.1/v0.3.0 (same release
keystore). From v0.2.x or earlier: uninstall once (the keystore rotated at
v0.3.0), then install.

## What works now

- **Cellular call recording** through the shell bridge: a capture process
  (`CaptureMain`, part of the APK) opens `VOICE_CALL` as UID 2000 and streams
  raw PCM to a dedicated second TLS session; the app wraps it into a WAV.
- **Auto-record** on detected incoming/outgoing cellular calls (Settings →
  Capture → Auto-record calls, default ON) — recording starts when the call
  connects and stops when it ends.
- **Record now** button on the Dashboard — manual recording anytime, the
  universal fallback; it keeps recording after the call ends until you stop it.
- **Capture probe** (Settings → Capture → Run audio probe): opens every
  privileged audio source × sample rate for a moment and reports which ones
  return real audio on this device, plus the fallback chain the recorder will
  follow (VOICE_CALL → downlink+uplink (dual, next step) → mic).
- **Crash safety**: a `journal.json` per recording; if the process dies
  mid-call, the next start sweeps the orphan, patches the WAV header sizes and
  marks it recovered — the audio survives.
- **Recording notification** with a live timer and a Stop action.

## Known limits (next M3 step)

- VoIP calls (WhatsApp etc.) are detected but not yet recorded — the
  MediaProjection playback-capture mix joins in M3 step 2.
- The downlink/uplink **dual-stream** capture (per-speaker files for the
  future ME/THEM labels) is implemented at the protocol level and lands as a
  recorder feature in M3 step 2; this release records the mixed stream.
- Recordings live in app-private storage; the library/player UI arrives with
  M4 (a file manager can already browse `Android/data/com.lmalakar.onecr/files/recordings/`).

## Fixed

- **CI green again**: `.github/workflows/android.yml` — the guard step's name
  is quoted (`"Guard: release notes for this tag must exist"`); the unquoted
  colon made GitHub reject the whole workflow on every push since v0.3.0.

## Install

1. Download `oneCR-v0.3.2.apk` **with a browser** (not a chat app) and compare
   the SHA-256 below if the installer complains.
2. Updates from v0.3.0/v0.3.1 install in place.
3. First time? Open oneCR → wizard → **Embedded ADB** → pair with the 6-digit
   Wireless-debugging code (details in the README).
4. Then: Settings → Capture → **Run audio probe** to see what your device can
   capture, and make a call.
