# oneCR v0.3.6 — oneCR records again: the shell capture engine, rebuilt on the true chassis

**v0.3.6** (versionCode 14) lands the M3 capture engine end to end on the
v0.3.5 module structure, and removes the root cause of the CI failure streak.

## 1. Capture engine — M3

A tiny framework-only entry point (`CaptureMain`) ships inside the APK and is
spawned as the adb-shell user (UID 2000 — the process that holds
`CAPTURE_AUDIO_OUTPUT`) via `CLASSPATH=<apk> app_process`:

- **Embedded ADB mode**: a dedicated streaming `shell,v2:` TLS session to the
  phone's own adbd carries the PCM; health pings and shell checks keep flowing
  on the main bridge untouched.
- **Shizuku mode**: the same capture process spawned by the shell service,
  piped back over binder FDs.

What works now:

- **Auto-record** on detected incoming/outgoing cellular calls (Settings →
  Capture → Auto-record calls, default ON) — recording starts when the call
  connects and stops when it ends; manual recordings survive the call.
- **Record now** on the Dashboard — manual recording anytime, the universal
  fallback.
- **Capture probe** (Settings → Capture → Run audio probe): opens every
  privileged audio source × sample rate briefly and reports which ones return
  real audio, plus the fallback chain the recorder follows (VOICE_CALL → dual
  → mic) — including the "opens but feeds silence" OEM quirk.
- **Crash safety**: the tested `WavWriter` + `RecordingJournal` pair from
  v0.3.4 writes and recovers the take; a journal is only written once the
  stream is actually up, and the per-app-start orphan sweep still marks
  crashed recordings.
- **Recording notification** with a live timer and a Stop action.

The app process itself never opens the microphone — no `RECORD_AUDIO`
permission is needed for the shell path.

*Known limit (next M3 step):* VoIP calls (WhatsApp etc.) are still detected
but not recorded — the MediaProjection playback-capture mix joins next, and
per-speaker downlink/uplink files with it.

## 2. Fixed

- **CI: Maven Central 429 root cause removed.** Since v0.3.2 the CI skipped
  the Maven mirror, so every cold build resolved Central artifacts directly
  from `repo.maven.apache.org` — which rate-limits GitHub runner IPs with
  HTTP 429 and defeats any retry loop. `settings.gradle.kts` now resolves
  Central-hosted artifacts from **Google's Maven Central mirror** on CI
  (global CDN, no rate limiting), keeping `mavenCentral()` as the fallback;
  local builds keep the Aliyun mirror. The v0.3.5 retry wrapper stays as
  belt-and-braces.

## Install

1. Download `oneCR-v0.3.6.apk` **with a browser** (not a chat app) and compare
   the SHA-256 below if the installer complains.
2. Updates from v0.3.5/v0.3.4/v0.3.3/v0.3.2/v0.3.1/v0.3.0 install in place
   (same release keystore).
3. From v0.2.x or earlier: uninstall once (the keystore rotated at v0.3.0),
   then install.
4. First time? Open oneCR → wizard → **Embedded ADB** → pair with the 6-digit
   Wireless-debugging code (details in the README).
5. Then: Settings → Capture → **Run audio probe** to see what your device can
   capture, and make a call.

Privacy: the capture streams only between oneCR and your phone's own adbd (or
the Shizuku server). Nothing leaves the device — no accounts, no telemetry,
no cloud. See PRIVACY.md.
