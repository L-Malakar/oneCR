# oneCR v0.2.3 — Back navigation, professional theming, green CI

**Polish release.** The shell now behaves the way a professional Android app
should: **system back never kills the app out from under you** — it walks you
back through the screens you visited, and only at the very start does it ask
for a second press to confirm the exit. The dark theme is fixed properly (the
v0.2.1–0.2.2 palette left half of Material 3's color roles unmapped, so
dialogs, menus and switches fell back to off-palette purple-greys), the
**About screen is redesigned** into a branded card, and the **GitHub Actions
CI is green again** after fixing the gradlew executable bit. Still
detection-only — recording arrives in M3 (v0.3.x).

## Highlights

- **Back navigation with exit confirmation.** System back now means "go back":
  - From the notification center → back to the screen you opened it from.
  - From Settings → Permission center / Event log (and the guided flow) →
    back to the settings root.
  - Between Dashboard / Library / Settings → back returns to the tab you came
    from (a real visited-tab history, remembered across process death).
  - With nothing left to go back to, the first press shows **"Press back
    again to exit"**; a second press within ~2 s exits. No more accidental
    exits.
- **Dark theme, fixed for real.** v0.2.3 maps **every Material 3 color role**
  in both dark and light modes. Fixes you can see:
  - Dialogs, dropdown menus, switches and text fields no longer use Material's
    baseline purple-grey — they use navy container tones that match the app.
  - The dark `secondary` role was near-black on navy (dark-on-dark); it is now
    a light slate.
  - Primary buttons in light mode use a deeper teal (white text was under 3:1
    contrast on the old teal).
  - The warning tone (bridge degraded, battery) uses a proper themed amber
    container pair instead of a hardcoded color.
  - The window background behind the Compose surface is now themed (navy at
    night, brand grey-white in light) — no more grey flash at launch.
- **Redesigned About screen.** Settings → About is now a branded card: a
  gradient header with the logo, tagline and version/build chips, followed by
  icon rows for Project home (opens GitHub), Privacy by design, License and
  the exact build, plus a "Re-run the setup wizard" button.
- **Green CI.** Every push was failing with exit code 126: repos pushed from
  Windows lose the executable bit on `gradlew`, so the Linux runner could not
  execute it. The workflow now makes `gradlew` executable before building, and
  CONTRIBUTING.md documents the permanent `git update-index --chmod=+x
  gradlew` fix. The tag-release job also survives a missing release-notes
  file, and superseded runs are cancelled automatically.
- **Bug fixes from a code review pass:**
  - Error events appeared **twice** in the notification center (once under
    Errors, again under Recent activity) — now only under Errors, pinned by a
    new unit test.
  - Dashboard "Recent events" showed the oldest of the last three events
    first — now newest-first, like every other feed.
  - A persisted-but-renamed tab name could crash the shell on restore — the
    restore is now guarded and falls back to Dashboard.
  - Hardcoded UI colors moved into the theme (`BadgeInk`), dead imports
    removed.

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Detection works on Android 8+;
  the embedded-ADB bridge (v0.3.0) will require Android 11+, checked at runtime.
- **Updating from v0.2.0/v0.2.1/v0.2.2:** same release keystore — installs in
  place, nothing to do. Updating from the v0.1.2 pre-release still needs the
  one-time uninstall first (that build used the lost original key).
- **Play Protect:** if installation is blocked with "This app can request
  access to sensitive data", that is the standard caution for any sideloaded
  app with call-log permissions — not a malware verdict. Tap **More details →
  Install anyway (unsafe)**, or disable the prompts under Play Store →
  Play Protect → Settings. Full story in `docs/COMPATIBILITY.md`.

## Known issues

- Same as v0.2.2: call-log enrichment may land a moment after the call ends on
  some OEMs; VoIP apps that suppress ongoing-call notifications aren't detected

  repair banner.
