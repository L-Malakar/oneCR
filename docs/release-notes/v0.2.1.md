# oneCR v0.2.1 — Light/dark theme + low-end device love

**Polish release.** The app now follows your phone's dark-mode setting by
default, you can pin it to light or dark from Settings, and a set of
low-end optimizations (plus honest messaging) confirm what the code already
did: **oneCR installs and detects calls on Android 8.0+, not just 11+.**
Still detection-only — recording arrives in M3 (v0.3.x).

## Highlights

- **Theme setting (System default / Light / Dark).** New *Appearance* card in
  Settings. The default, **System default**, follows the phone's dark-mode
  toggle; Light and Dark pin the palette regardless of the OS setting, and you
  can switch back to System at any time. The choice persists across restarts
  and applies instantly.
- **Android 8+ support, confirmed and documented.** The install floor has been
  Android 8.0 (API 26) since v0.1.2 and detection already falls back correctly
  (`PhoneStateListener` on API 26–30, `TelephonyCallback` on 31+, guarded
  foreground-service typing on 34+, notification permission only asked on 33+).
  The README, onboarding wizard and compatibility doc now say so instead of
  implying 11+. Only the v0.3.0 embedded-ADB bridge will need Android 11+ —
  Shizuku mode works on 8+ today.
- **Low-end device optimizations.**
  - On Android Go / low-RAM devices (`ActivityManager.isLowRamDevice`), the
    privilege-bridge health ping runs every **2 min instead of 30 s** — fewer
    idle wakeups; binder-death callbacks still fire instantly.
  - Resource shrinking now strips the unused locale resources bundled by
    AndroidX (~40+ locales) — smaller APK and a smaller resource table to load
    on 1–2 GB RAM phones.
  - The APK ships **all ABIs** (arm64-v8a, armeabi-v7a, x86, x86_64), so
    32-bit Android 8 budget phones install it too.
- **3 new unit tests** for the theme-mode persistence contract (25 total).

## Install & update

- Install floor: **Android 8.0 (API 26)+**. Detection works on Android 8+;
  the embedded-ADB bridge (v0.3.0) will require Android 11+, checked at runtime.
- **Updating from v0.2.0:** same release keystore — installs in place, nothing
  to do. Updating from the v0.1.2 pre-release still needs the one-time
  uninstall first (that build used the lost original key).
- **Play Protect:** if installation is blocked with "This app can request
  access to sensitive data", that is the standard caution for any sideloaded
  app with call-log permissions — not a malware verdict. Tap **More details →
  Install anyway (unsafe)**, or disable the prompts under Play Store →
  Play Protect → Settings. Full story in `docs/COMPATIBILITY.md`.

## Known issues

- Same as v0.2.0: call-log enrichment may land a moment after the call ends on
  some OEMs; VoIP apps that suppress ongoing-call notifications aren't detected
  until M3's manual record; Shizuku dies on reboot by design and oneCR shows a
  repair banner.
- The embedded-ADB bridge (no Shizuku needed at all) lands in v0.3.0.
